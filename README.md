# 工程检测报告 · 交付契约平台（DCP）

面向工程检测机构向**施工单位、监理、审计**交付报告、缺陷摘要、定位与附件索引的“交付契约平台”。
纯前端实现：**React 18 + TypeScript + Vite + IndexedDB + WebWorker**，无后端、无外部服务依赖；
提供 Docker / Compose 一键静态托管。

平台把题目中的硬规则全部做成了可运行、可测试的机制，而不只是展示页面：

- **字段契约**：类型、单位、舍入精度、空值含义、允许枚举、数据来源、可见角色全部显式注册（`src/domain/contracts.ts`）。
  - 坐标按 **0.1 m** 投影；裂缝宽度以 mm 保留 **0.1 mm**（12.03→12.0，14.96→15.0）。
  - **先判检出限再舍入**：0.04 mm 输出 **`<0.1 mm`**，绝不会先 `toFixed(1)` 变成 `0.0`。
  - `null` 保留业务含义（未测量 / 未采集坐标≠原点 / 状态未填报≠未整改）。
- **授权六维交集**：项目 ∩ 施工标段 ∩ 接收角色 ∩ 字段组 ∩ 用途 ∩ 有效期（含撤销），逐维给出通过/拒绝轨迹（`src/domain/auth.ts`）。
- **投影编译器**：固定报告修订 + 固定许可版本生成投影，对每个“实体 × 字段”记录输出 / 契约化处理 / 过滤原因（`src/domain/compiler.ts`）。
- **包校验器**：必需字段、单位、HMAC 签名、附件引用与 SHA-256、报告哈希/来源版本、授权版本六项检查（`src/domain/validator.ts`）。
- **两种交付模式**：
  - **预物化签名包**：生成时 pin 报告修订/来源哈希/契约版本/许可版本并签名，重复交付快、可离线审阅；**生成与实际释放（下载）两次复核授权**。
  - **动态投影**：每次请求按当前许可实时编译并实时校验，授权变化立即生效。
  - 两者在授权撤销/报告修订后都**不得让新请求释放旧包**；旧包状态置为 `release_blocked` / `superseded`，但记录与**已签署交付的审计摘要永久保留**，并可按当前授权重建。
- **回执账五态**：`传输已收到 / 结构已解析 / 语义已确认 / 提出质疑 / 被更正`。
  - “传输已收到”**永远不会**被推导为语义确认；
  - 同一接收方对同一修订同时确认与质疑 → `conflict`，须管理员**冲突裁定**；
  - 账本键为 `接收方::报告#r修订`，**修订之间严格隔离**（r1 的确认不能充当 r2 的确认）。
- **离线工作区**：仅允许编辑**带基线版本（报告修订+哈希+包ID）的审阅意见**与**回执草案**，全部落 IndexedDB；
  恢复联网后按**意见ID幂等合并**（同 ID 不重复，支持并行编辑冲突选择），并依据修订差异自动打
  **“需对修订 N 重审”**标记；已签名交付包只读，任何改写尝试被拒绝并写 `offline_edit_blocked` 审计。
- **历史审阅界面**：修订链与哈希/签名校验、r1→r2 字段差异、意见基线与重审标记、完整只追加审计账本。
- **抽检覆盖校正后的缺陷密度**（`src/domain/sampling.ts` + 「抽检覆盖校正」工作台）：解决“承包商缺陷条数不可直接比较”的问题。
  - 每批次保存**计划检查管段框、实际检查长度（线性桩号区间）、选段原因、抽样概率 π 与未检原因**；
    观测器把缺陷区间**映射到实际覆盖长度**，覆盖区间求并集**去重叠**，缺陷观测相交也合并为 distinct。
  - **两条估计路线都针对同一登记管网范围**输出单位长度缺陷率（处/km）：
    - **设计权重（Horvitz–Thompson，w=1/π）**：保持目标总体定义，小概率段以 1/π² 放大方差；
      无受控覆盖的层不提供信息，总体标记“部分不可识别”。
    - **分层校准（管龄/材质/风险层，层实测率 × 层登记长度）**：稳定性更好；
      无覆盖层只能借用合并率（显式 `imputed` 标记），依赖“层内可比”假设。
  - 输出每公里目标管网缺陷率、标准误、95% 置信范围、变异系数与**未覆盖部分**；
    **现场观察数与加权估计严格分区**，未覆盖长度按原因单列、**绝不补零**；
    **无抽样概率的临时加检只列补充证据**，不进入总体估计、不外推。
  - 内置题目样例：同一 100km 登记管网（高风险 20 / 中风险 30 / 低风险 50 km），
    甲查高风险 10km 见 8 处、乙查全网 30km 见 9 处，可直接核验未加权排名与校正后估计的变化、方差与覆盖率。

## 一、本地启动

要求 Node.js ≥ 20（开发与验证使用容器内 Node v22.14.0 / npm 10.9.2）。

```bash
npm install        # 若 npm 缓存目录有权限问题：npm install --cache /tmp/npmcache
npm run dev        # http://localhost:5173 （已配置 --host 0.0.0.0）
```

生产方式：

```bash
npm run build      # tsc 类型检查 + vite 产物到 dist/
npm run preview    # http://localhost:4173
```

运行自动化验证：

```bash
npm test           # vitest run：领域单测 + jsdom 全流程渲染冒烟（共 44 个用例，5 个测试文件）
```

## 二、Docker / Compose 一键启动

仓库已包含 `Dockerfile`（多阶段构建：node:22-alpine 构建 → nginx:1.27-alpine 托管）、
`docker-compose.yml` 与 SPA/Worker MIME 所需的 `nginx.conf`。

```bash
docker compose up --build -d
# 打开 http://localhost:8080
```

或：

```bash
docker build -t dcp .
docker run --rm -p 8080:80 dcp
```

> 说明：当前交付环境未安装 Docker，因此镜像构建/运行未在本环境实际执行；上述配置为标准多阶段构建，
> `npm run build` 产物已在本环境验证可由 `vite preview`（等价静态服务器）正常托管。

## 四、本题的验证方式（建议照此走一遍）

打开应用登录后，默认进入 **「场景推演」** 页，这是一条带实时完成度的 11 步引导剧本，
每一步都有真实动作与可核验结果：

1. 以施工方身份进入。
2. 系统已预物化 P / R1 / 修订1 的三个角色签名包（首次启动播种到 IndexedDB）。
3. 点 **运行投影自检**：断言 B1 仅得到 D-P-001/002/004；D-P-003 被标段过滤；
   D-P-001 宽度 `12.0 mm`；D-P-002（0.04mm）显示 `<0.1 mm`；A-201 照片被过滤并记录原因。
4. 点 **切离线并写入意见**：网络开关变离线，意见 **“缺陷已复测…”** 以固定 ID
   `CMT-SCENARIO-001`、状态 `local-only` 写入 IndexedDB，基线固定为 R1#r1 + 报告哈希 + 包ID。
5. 点 **撤销施工方许可**（模拟离线期间授权撤销）。
6. 点 **签署并发布修订2**：D-P-001 裂缝宽度 12.0→**15.0 mm**，r1 签名/哈希保留，
   并自动给 r1 账本登记“被更正”。
7. 点 **恢复联网并同步合并**：意见按 ID 合并为 `synced`，基线仍为 r1，
   自动标记 **需对 r2 重审**，变化字段=裂缝宽度、影像摘要。
8. 点 **尝试释放旧的修订1包**：释放闸门同时给出
   “报告已修订至 r2…”与“许可已撤销…”双重拦截，包置 `superseded`，审计保留签署摘要。
9. 点 **登记“传输已收到”**：R1#r2 账本状态仅为“传输已收到”，**语义确认位 false**。
10. 依次点 **登记语义确认**、**同时提出质疑**：账本进入 `conflict`；
    切换管理员后填写理由并 **裁定：质疑成立**，账本落 `adjudicated_question`。
11. 到 **版本与审计 / 回执账 / 离线审阅 / 签名交付包 / 交付编译 / 契约与授权** 各页核对持久结果。

其他专项验证：

- **抽检覆盖校正**（侧栏「抽检覆盖校正」页）：
  1. 顶部「样例核验：甲 vs 乙」表直接给出同一 100km 登记管网（NET-100）的对比：
     未加权口径甲 8 处/10km（朴素率 0.8）、乙 9 处/30km（朴素率 0.3）——按总条数与按朴素率排名互相矛盾，均不可用；
  2. 切换 **设计权重**：甲 HT 估计 0.16 处/km（仅高风险层有信息，标记“部分不可识别”，CV 35.4%，覆盖率 10%），
     乙 0.2655 处/km（三层均抽样，覆盖率 30%，可完全识别）；95% 置信范围随表披露，可与 `src/domain/sampling.test.ts` 中的手算公式逐项对照；
  3. 切换 **分层校准**：甲的中/低风险层显示 `imputed 借用` 徽章并给出“层内可比”假设告警；乙各层均为本层实测率；
  4. 查看 **未检部分** 表（交通导改/CCTV 故障/进场许可等原因，未覆盖 90km 与 70km 单列不补零）
     与 **临时加检** 面板（甲 1 处/2km 无概率，仅补充证据、不入加权）；
  5. 「新建批次 / 编辑当前批次」可维护抽样框、覆盖区间、未检项与观测，保存后落 IndexedDB（刷新仍在），
     受控段缺少 π 或覆盖区间起止非法时保存校验会拦截。
- **交付编译**：五个预设（施工方 / 监理索引 / 审计修订链 / 审计访问 Q 被拒 / r2 动态投影），
  编译+签名+校验真实运行在 **WebWorker**，页面显示 Worker 耗时；下方有完整字段级原因表与校验报告。
- **签名交付包**：可释放下载 JSON 包、**模拟传输篡改**后重新校验会看到签名 FAIL、
  可对被取代的包 **按当前授权重建 r2 包**、可演示“尝试离线改写签名内容”被审计拦截。
- **契约与授权**：字段契约全表 + 六维交集模拟器 + 许可撤销/换发（版本号漂移也会阻止旧 pin 包释放）。
- 刷新浏览器后登录态、意见、回执、包、审计均仍在（IndexedDB 持久化）。

## 六、目录结构

```
src/
  types.ts                     # 全部跨层领域类型
  domain/
    contracts.ts               # 字段契约注册表（精度/单位/空值/枚举/来源/角色）
    format.ts                  # 舍入、坐标、测量值（检出限优先）、枚举/时间格式化
    sha256.ts                  # 纯 TS SHA-256 / HMAC-SHA256（不依赖安全上下文）
    hash.ts                    # 规范化 JSON、哈希、签名、ID
    seed.ts                    # P/Q 项目、R1 r1+r2、缺陷/附件、账号、许可
    auth.ts                    # 六维交集 + 释放前授权版本复核
    compiler.ts                # 投影编译器 + 字段级原因
    validator.ts               # 包校验器（6 类检查）
    package.ts                 # 物化/签名/清单/下载序列化
    receipts.ts                # 回执账本推导与冲突状态
    merge.ts                   # 意见 ID 合并、冲突、重审标记
    sampling.ts                # 抽检覆盖并集去重、观测映射、HT 设计权重/分层校准估计与样例
  db/idb.ts                    # IndexedDB 封装（7 个 object store，含 samplingBatches）
  workers/delivery.worker.ts   # 编译/构建包/校验 Worker
  workers/protocol.ts
  state/workerClient.ts        # reqId 配对的 Worker 客户端
  state/store.tsx              # Context 全局状态 + 全部业务动作 + IDB 持久化
  components/                  # 8 个工作台 + 共享 UI + 投影/校验组件 + 登录 + 批次编辑器
  App.tsx / main.tsx / styles.css
src/**/*.test.ts(x)            # 44 个自动化用例
Dockerfile / docker-compose.yml / nginx.conf
```

## 七、演示边界

- 认证为前端模拟，不是真实身份系统；HMAC 密钥内置在 `src/domain/hash.ts`，
  真实部署应替换为 KMS/HSM 持有的非对称签名密钥，并增加服务端授权策略点（PDP）与对象存储。
- “服务端意见/回执”用同一浏览器 IndexedDB 中的不同数据集模拟，用于真实演示同步合并语义；
  接入真实后端时只需把 `state/store.tsx` 中的 kv/IDB 读写替换为 API，领域层与 Worker 无需改动。
